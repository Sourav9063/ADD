# Integrate UI Components

## Goal

Make web-design guidance produce coherent screens from the repository's existing design
system and components, with intent, hierarchy, risk, and complete states decided before
implementation.

## Work

1. Correct authentication guidance against current NIST and OWASP requirements.
2. Add one orchestration skill for multi-component page and screen work.
3. Narrow component-skill routing so focused component tasks stay cheap and composed UI
   starts with orchestration.
4. Align the catalog, durable knowledge, and repository memory.
5. Remove prohibited dash punctuation and validate the complete staged change.

## Acceptance

- Authentication guidance does not enable account enumeration and distinguishes the
  password minimum for single-factor and multi-factor authentication.
- Multi-component UI work inspects existing tokens and components before adding new ones.
- The workflow records user intent, hierarchy, component ownership, applicable states,
  responsive behavior, and verification.
- Focused component requests still route directly to their component skill.
- Catalog counts, links, metadata, YAML, style, and staged contents agree.
